# 开发协作记忆模板

这个模板用来保存长期稳定的协作偏好和默认工作流。  
它应该保持通用、明确，并且足够项目中立，方便跨 agent 复用。

## 1. 工作方式

- 中大型任务默认先分析，再对齐当前代码和产品意图，再给出可落地方案，然后再实现
- 页面重构、入口调整、高风险行为变更或大改造，先写方案文档
- 默认优先清楚边界、低耦合、可维护、可回滚
- 没有明确要求时，不要顺手扩改到别的文件、模块或流程
- 如果任务边界还没清楚就开始实现，先停下来跑 `current-task-capsule`

## 2. 默认 workflow skills

- `current-task-capsule`
  - 中大型任务开始前先收口：唯一目标、不改范围、关键文档、代码入口、验收标准、blocker、下一步
- `high-risk-preflight`
  - 改高风险链路、状态判断、支付/登录/订阅、持久化、远程开关前先做边界预检
- `handoff-retrospective`
  - 真正有代码改动后，总结改了什么、没改什么、验证情况、风险和下一步

运行时映射：

- Codex skills 放在 `.agents/skills/<skill-name>/`
- Claude Code skills 放在 `.claude/skills/<skill-name>/`
- skill 目录名应和 `SKILL.md` 里的 `name` 保持一致

## 3. 人和 agent 的职责分工

- 人：
  - 最终产品判断
  - 高风险业务决策
  - 真机 / 手工验证
- Agent：
  - 在明确范围内实现代码
  - 做轻量自检
  - 输出 docs、handoff、风险总结
  - 明确说清假设、风险和未验证项

## 4. 沟通偏好

- 说话直接一点、具体一点
- 假设和风险要写清楚
- 如果需求含糊，先查本地上下文，再决定要不要追问
- 如果某个捷径会明显拖坏后续维护，要把原因讲清楚，并给出更稳的替代方案

## 5. 文档规则

- 长期基线文档保持少量、稳定
- 临时方案和 retrospective 用归档方式管理，不要全堆在一个目录
- handoff 要尽量做到下一轮能直接接上
- 文档里优先写文件路径、边界、下一步，不要写一大段泛总结

## 6. 更新规则

如果在协作里形成了新的稳定偏好或项目规则，在当前任务结束后再回写到项目 memory。
