# Skill 维护规则

## 什么时候新增 skill

只有同时满足下面这些条件时，才值得新增一个 skill：

- 同一类任务模式反复出现
- 这个工作流已经比较稳定
- 输入和输出都清楚
- 它确实减少了重复解释
- 不会鼓励 scope creep

## 什么时候应该先改已有 skill

- 如果自动触发偶尔漏掉，先收窄或改清楚 `description`
- 如果输出形状不顺手，优先改 `assets/*.md` 模板
- 如果两个 skill 开始重叠，先收窄其中一个，而不是再造一个更大的第三个 skill

## 什么情况不该技能化

- 一次性任务
- 依赖人工截图/标注的像素级 UI 微调
- 高风险业务逻辑重写
- 探索性算法实验
- 那种“什么都做”的大而全工作流

## 什么时候降级或移除一个 skill

- 如果默认 skill 开始变吵，先取消它的默认地位
- 如果还是乱触发，就收窄它的 `description`
- 如果继续没有真实价值，就删除或归档

## 建议节奏

- 默认 skill 保持少量、稳定
- 专项 skill 一次只加 1 到 2 个
- 少而清楚的 skill，比大而重叠的一堆 skill 更有用
